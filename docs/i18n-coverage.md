## Expected errors and action boundaries

`UiError.key` is restricted to `errors.*`. Actions transport `errorCode` and `fieldErrorCodes`; consumers derive visible text from the current translator. No exception message is used as display text. Known error classes map to stable codes, and unknown errors use the generic message. Validation handles explicit schema codes as well as default Zod invalid-type, format, lower-bound and upper-bound issues.

## Domain and data boundaries

- `lib/i18n/core-messages.ts`: matched English/Hebrew catalog for route bodies, metadata, confirmations, status/option labels, plural/count messages and all 295 distinct icon labels. Icon IDs and submitted colors remain unchanged.
- `lib/i18n/domain-messages.ts` and the explicit locale arguments in limit, window, challenge and name helpers localize display only. Weekday masks, date calculations, IANA timezone IDs, canonical dates and form values remain unchanged.
- `SubmittableChore.reasonCode` transports structured assignment/turn/shared-cap/done states. The UI reads this descriptor. Legacy English `reason` remains available to existing domain callers; no matching against stored text is performed.
- New Hebrew registrations seed localized category names. Existing categories and records are never renamed by switching locale. Family-scoped category updates and stored names are covered by integration tests.
- Activity dates use active locale plus family timezone; number animations use explicit locale. Mixed-direction user text uses `bdi`, text fields use `dir=auto`, and email/numeric fields use LTR.

## Separate batches and deliberate exclusions

- Marketing landing pages, comparison/guides/calculator prose and legal body content are Task 5. Shared site header/footer navigation is covered here.
- Notifications, PWA/install strings, manifest and recipient-specific notification locale are Task 6, owned independently. Action notification payload text is intentionally left for that batch.
- Historical ledger prefixes (`Put back:`, `Challenge:`), snapshots, export values, technical/internal diagnostics and saved names are not translated or rewritten.
- Raw icon registry English labels are retained as metadata for existing callers; visible picker labels use the typed icon-label catalog keyed by immutable icon IDs.

## Verification

- New focused tests: Hebrew category creation + family isolation/data preservation; wrong password and field validation; repeated PIN failures and lock state; insufficient points; setting and clearing a reward goal; unknown exception masking; complete Hebrew dynamic summaries; catalog parity.
- Existing domain helper tests cover English regression behavior. Existing auth, catalog, points, category and redemption integration checks are run with this batch; the controller runs final whole-suite and browser/visual checks.
- `tests/e2e/i18n.spec.ts` uses Hebrew selectors after a Hebrew switch and verifies Hebrew field and password errors.

Unchanged presentation-only shells: `ScreenHeader`, `Field`, `IconButton`, `Card`, `Chip`, `Skeleton`, `PageSkeleton` and `ConfirmDeleteDisclosure` receive translated labels/content from the listed callers or contain decorative UI only. The `/dashboard`, `/me`, `/redeem` and `/award/[kidId]` loading routes contain decorative skeletons and no authored visible text.
